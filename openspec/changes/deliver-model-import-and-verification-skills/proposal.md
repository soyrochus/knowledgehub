# Proposal

## Why

Analysts should use their existing coding-agent environment to create a complete governed model, rather than needing Modelarium's unimplemented AI module. A real rich-design reference case is needed to prove that the generic ontology/tools can preserve source meaning and the working UI, not merely upload documents or emit a node list.

## What Changes

- Distribute `knowledgehub-import` and `knowledgehub-verify` with portable core instructions, general references and thin host-specific packaging.
- Guide source-authority analysis, complete typed interpretation, bounded clarification/review and invocation of the deterministic C3 tools.
- Supply a KnowledgeHub-local Memento source fixture, neutral plan, coverage inventory and semantic acceptance queries as example data, plus an unrelated-domain reuse fixture.
- Demonstrate actual standalone generation, validation, source/trace verification, uncertain-outcome recovery and reopen through supported local Codex, Claude Code and GitHub Copilot execution modes.
- Keep descriptive UI/rules as exact artifacts with meaningful bindings; do not infer actual Memento accounts, provider activity, test passes or human acceptance.
- This is C4 of MM-SL-01. Actor: developer/analyst invoking the skills on a source package. Completion: verified native model and truthful source/interpretation/coverage evidence without Modelarium installed or running. Hard prerequisites: C1–C3.

## Capabilities

### New Capabilities

- `agent-model-authoring`: Reusable external-agent import and independent verification workflows over supported native tools.
- `rich-design-reference-model`: Complete, source-bound rich-design reference data and independent semantic/coverage evidence.

### Modified Capabilities

None. The existing KnowledgeHub self-description is a different governed model and is not rebuilt or reclassified by this change.

## Impact

KnowledgeHub only: a new distributable skills package, its references/installation guidance, fixture data/plans/query manifests and executed-evidence procedures. Trace: ontology proposal §§4–8, 12–14, 17, 19/21.10 and the practical manual's slice/review method; MM-SL-01 first user story.

Memento entities, attributes, IDs/counts and UI values are fixture/model data only; generic tooling and ontology contain no domain-specific branches. Source examples may be copied with provenance from the explicitly selected read-only package into this repository during implementation; the result is independently usable without a Modelarium checkout. No editing existing generated agent skills, Modelarium artifacts, app integration, in-app AI, arbitrary stored-rule execution, legacy compatibility, old_hub access/reset, source-app implementation or crate publication. Human and unexecuted host acceptance gates remain separate from automated native checks.
