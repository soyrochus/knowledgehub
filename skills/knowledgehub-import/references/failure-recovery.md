# Walkthrough and failure exercise

Use the four separate JSON inputs in authoring-example.json with a fresh source,
run and destination. Discover the current catalogue, capture, prepare and assess
before create. Read assessment.json and the exact sourced gaps; a valid draft is
not necessarily complete. Invoke knowledgehub-verify in a fresh session using
the retained run and explicit current host actor/grants.

For a controlled disposable exercise, set
`KNOWLEDGEHUB_MODEL_FAULT=after-commit:authoring:model` only on the create
command. The process exits 86 after native acceptance and before retaining its
response. Preserve the destination and run. In another process invoke resolve,
then resume with the same WORK and current HOST.json. Inspect the two original
operation IDs, original model receipt and exact baseline. Do not substitute a
new operation, change the plan or reset the destination. This fault hook belongs
to the local host exercise; it does not execute imported business code.

Expected diagnostics and retained decisions:

| Situation | Required result |
| --- | --- |
| Old catalogue, string selector or authoring format | Explicit incompatible/invalid input; no translation |
| Missing binary or local execution | Unmet prerequisite; no claimed import |
| Source conflict | Retain exact support in authority.unresolved_conflicts; independent coverage remains incomplete |
| Duplicate or unordered native Set | Native invalid assessment; review supplied data rather than deleting inconvenient members |
| Changed original or prepared plan | New run/destination required; original intent cannot be resumed |
| Current actor lacks recovery authority | Denial remains denial, never operation absence |
| Lost commit response | Resolve the original operation under current authority before same-run resume |
| Page, subject or visited budget reached | Explicit failure/truncation; no claim of exhausted semantic coverage |

The native CLI integration tests exercise these boundaries. The independent
equipment forward test also encountered the Set ordering diagnostic and
corrected its authored data before publication. These are technical exercises;
human meaning review and application acceptance remain separate.
