---
name: knowledgehub-import
description: Interpret an explicitly selected design and working UI source package into a fresh native KnowledgeHub model, with exact sources, typed definitions, recoverable publication and independent coverage verification.
---

Use a local execution-capable agent host with the current knowledgehub-model
binary. Read the supplied package's ownership hierarchy before modelling, then
read [the native tool contract](references/model-authoring.md). Use the [exact JSON example](references/authoring-example.json) when authoring
config/host/plan/coverage files; its four object members are separate input files.
Obtain explicit
source, new destination, private run directory, scope and current host authority.
If local execution or the matching catalogue is unavailable, report that unmet
prerequisite; do not simulate an import.

Inventory every supplied file, exact original digest, media, authority, duplicate
rendition, local dependency and exclusion. The designated working UI is design
content, irrespective of its directory name. Analyse HTML/CSS/scripts, controls,
states, confirmations, errors, permissions, command effects and assets as data.
Keep binary originals separate from supplied extraction/locator artifacts.

Create a reviewable typed plan and independent source obligation/query inventory.
Use actual catalogue tokens and native kernel variants. Preserve stable source
identifiers, shared story placements/cuts, direct lifecycle subjects, logical
application targets, inherited schemas and honest planned realization. Add no
application-specific built-in ontology types. Source-bound narrative/Body and
artifacts can retain detail beyond structured formalization; state that limit.

Resolve material source conflicts with an authorized person when their input is
needed; otherwise retain exact conflicting support and an unresolved decision.
Agent interpretation is not human review. Simulated research remains simulated;
absent implementation, accounts, provider actions and application tests remain
absent. Do not invent defaults or use gaps to excuse malformed supplied values.

Run catalogue -> capture -> prepare -> assess -> create with explicit files and
current host inputs. Before reporting completion, invoke the independent
[knowledgehub-verify workflow](../knowledgehub-verify/SKILL.md). Structural
completeness cannot replace source coverage. Report every unexhausted query,
unsupported item, source gap and unresolved interpretation.

After interruption preserve the run and destination. Use resolve, then same-run
resume. Never reset stores, edit accepted backend files, change original intent,
or use a new operation ID to bypass uncertainty or denial. Source changes require
a new reviewed run and fresh destination. Respect the user's authorized scope.

Return native directory, scope, exact head, baseline, catalogue/profile,
source/mapping/coverage artifacts and known receipts. Separate source coverage,
native validity/completeness, interpretation review, implementation evidence and
human acceptance. For a reproducible example read
[the fixture walkthrough](references/fixtures.md).
Use the [failure and recovery exercise](references/failure-recovery.md) on a
disposable run when checking a new host installation.
