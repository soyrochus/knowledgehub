## Why

Deleting compatibility paths must not delete the verified publication, provenance and query guarantees. The user requested a complete 0.10.0 verification and fresh canonical self-model after the three preceding changes, retaining the previous instance as old_hub by their own rename.

## What Changes

- Audit the old seed/full safety cases against the sole API and port any uncovered guarantee. Remove obsolete cross-version matrices rather than preserve a historical test count.
- Run one fresh complete native/host/format/Clippy/release-build batch against final 0.10.0 inputs using existing Rust 1.99.1, then capture exact current sources/PDF/extraction and validated bindings.
- Check that hub is absent for the first cutover rebuild. If the old instance remains there, stop before changing it and report that the user's rename is still needed. Never rename, delete, read through a compatibility adapter or import old_hub.
- Create the new canonical Hub through current ordinary APIs, register the complete ontology, populate the current self-model and create new A/B/history/original receipts.
- Drain/reopen/compact/scrub; verify original retries, all catalogue coverage, actual neighbour/text/composite reads, cold/warm metadata reuse, sealed hashes and unchanged quotas. Keep rent/late-link fixtures separate.
- Publish fresh version/build/input-bound evidence and a canonical guide with actual sizes/counts/gaps. Historical observations and source ownership remain distinct.
