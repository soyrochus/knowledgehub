# Small terminal teaching models

`fruittrucks/` retains four public course/session-4 source documents from
`aisolutioneng`. `source-origins.json` records their original paths, lengths and
SHA-256 digests. The instructor-only fact sheet is excluded. `build.py` authors a
bounded typed interpretation with explicit gaps, rather than inferring a full
process implementation. R8 acknowledgement, Q1 delivery timing, proposed expiry,
open policy questions and invented route examples retain their source status.
Two deliberately equal requirement labels exercise identity disambiguation.
The independent FruitTrucks report intentionally remains `incomplete` with
`source_coverage: false` because the manual/interview authority conflict is retained;
native validity and exact source/query checks do not resolve that conflict.

`equipment/` retains the unrelated maintained equipment-design plan and sources,
including a governed extension hierarchy and stored throwing rule sentinel.
Exploration never executes that artifact. Both models use the same generic client.
Source accounting and native validity do not establish complete formalization,
approved production policy, running software or human acceptance.

The retained FruitTrucks authority conflict is intentional: independent authoring
verification reports `status: incomplete` and `source_coverage: false`, while
native validity and its bounded query/source checks pass. Equipment reports
`verified` source accounting. Both models remain structurally incomplete drafts.
Do not erase the manual/interview conflict or promote the proposed expiry to make
a verification label green. The dated evidence retains the original reports.

Maintainers prepare new instances through the existing authoring/public APIs:

```sh
cargo build --bin knowledgehub-model --bin knowledgehub-client-host --example model_successor --example terminal_fixture_handover
python3 scripts/prepare-terminal-models.py target/terminal-client/fresh-workshop
```

An occupied destination is refused. Do not reset it or reuse its receipts as
evidence for another run. The preparation performs capture, plan preparation,
assessment, creation, resolution and independent verification; ordinary native
changes create successor B and a superseded baseline definition. Native compaction
and reopen precede reader-B receipt/source checks. Exact handovers retain baseline
references, original operation IDs, actors, fingerprints, heads, affected vectors
and original artifact identities. Plans and stored data revisions are distinct.

Writers and hosts drain before any packaging/copy. Relative `workspace.json`
entries explicitly grant Open/Read/ReadHistory to reader B; the companion workspace
grants only Open/Read. Known baselines are exact validated references, not inferred
generation anchors. Stores stay under the chosen disposable destination.

The package builder includes only ordinary files and refuses symlinks/AppleDouble
sidecars. macOS metadata must not become spurious native pack files. Do not remove
native integrity checks or manually repair a real Hub to work around packaging.
The retained repository `hub/` and `old_hub/` are never opened or source-captured.
